# FPGA design

Source: [`fpga/fy_fpga.v`](../fpga/fy_fpga.v) (top level, `dds_ch`, `f2inc`, `mcp_drv`) and
[`fpga/freq_counter.v`](../fpga/freq_counter.v). Device EP4CE6E22C8N, Quartus Prime Lite.

## Overview

```
            SPI (SCK domain)                      system clock 125 MHz
 STM32 ─> SPI slave ─ toggle sync ─> register file (64 × 32) ─┬─> flash controller ─> wave RAM CH1/CH2
                     <─ read mux <───────────────────────────┤        ▲ W25Q16
                                                              ├─> dds_ch CH1 ─> DAC CH1, TTL A/B, Sync OUT
                                                              ├─> dds_ch CH2 ─> DAC CH2, TTL C/D
                                                              │      (CH2 output = modulation signal of CH1)
                                                              ├─> freq_counter (Counter / Trig IN)
                                                              ├─> calibration (K from 0x22:0x23)
                                                              └─> relays; MCP4822 drivers (10 MHz domain)
```

Resource use (v0.18): about 90 % of the logic elements, 22 of 30 multipliers, both wave RAMs
in M9K blocks; timing is met at 125 MHz with a small margin (~0.2 ns, slow 85 °C model).

## Clock domains

| Domain | Clock | Content |
|---|---|---|
| SPI | `spi_sck` (18 MHz) | shift registers, bit counters |
| system | PLL clk0, 125 MHz | everything else |
| DAC2 | PLL clk1, 125 MHz + 6 ns | CH2 DAC clock output only |
| pulse width | PLL clk2, 125 MHz | counter pulse width state machine |
| counter input | `cnt_in` / `trig_in` | Gray-coded event counter |
| MCP | `clk10` (TCXO) | MCP4822 drivers |

Crossings: SPI → system via toggle flags (address and data word), CS through a 3-stage
synchroniser; counter values Gray-coded; MCP values sampled twice in the 10 MHz domain. The
constraints are in [`fpga/fy_fpga.sdc`](../fpga/fy_fpga.sdc).

## SPI slave and register file

* Address and data bits are counted separately. Both counters are reset asynchronously while
  CS is high, so every frame starts aligned (needed for the 16-bit VCO-IN frames).
* A write is committed at the end of a frame (CS rising, detected in the system domain) if
  an address and a 32-bit data word were received in that frame.
* Writes to 0x2F generate `ph_sync` (load the start phases), writes to 0x22/0x23 restart the
  calibration.
* A frame with exactly 16 data bits and no address is a VCO-IN sample and goes to 0x2D.
* Reads: the address of a read frame selects the read word through a two-stage multiplexer
  that only contains the registers the firmware actually reads (0x02, 0x03, 0x0C, 0x15, 0x1F,
  0x3A; 0x1B = 0). Because there is no general read-back, synthesis removes all register bits
  the logic does not use (this saved about a third of the logic).

## Flash controller and wave RAMs

* SPI mode 0 at 31.25 MHz (system clock / 4), command 0x03 (read).
* Waveform transfer (rising edge on 0x12): 16384 bytes from the address in 0x17, unscrambled
  and assembled into 8192 × 14-bit samples, written into the wave RAM selected by 0x0F.
* Single byte (rising edge on 0x0D): one byte from 0x17, returned in 0x0C with the bit order
  the firmware expects; busy flag in 0x15.
* Writing to the flash (0x11, 0x13, 0x14, 0x16) is **not implemented**.
* Both wave RAMs start with a sine (`sine8192.hex`, generated by `gen_sine.py`).

## DDS channel (`dds_ch`)

### Frequency and phase

* `f2inc` converts the 64-bit frequency (0.1 Hz units) into a 48-bit phase increment:
  `inc = F · K >> 16` by sequential shift-and-add (new value every 37 clocks).
  Resolution: 125 MHz / 2^48 ≈ 0.44 µHz.
* 48-bit phase accumulator; the wave RAM is addressed with the upper 13 bits.
* `ph_load` (write to 0x2F, or Sync IN edge in uplink slave mode) loads the start phase.

### Waveforms

| Mode | Generation |
|---|---|
| table | wave RAM output (registered), 8192 samples per period |
| square | high while phase < threshold, **edge interpolation** |
| trapezoid | segment detection on the upper 14 phase bits, slope multiplication, limiting |
| CMOS / pulse | like square, unipolar (mid scale … full scale) |
| Adj-Pulse | like CMOS with a threshold computed from the pulse width |
| DC / off | mid scale |

**Edge interpolation.** With a DDS clock of 125 MHz a plain square wave has edges that jump
between sample positions (8 ns jitter). When an edge falls between two samples the design
outputs the fraction of the sample interval during which the signal was high
(`x / inc`, x = phase past the edge). The analog reconstruction filter turns this into an
edge at the correct sub-sample position; simulated jitter drops from 6.5–8.5 ns to about
0.6 ns. `1/inc` is computed once per frequency change (normalisation + 13-bit reciprocal).

**High threshold.** Square/CMOS use the duty cycle as a 48-bit phase threshold. Adj-Pulse
uses `width · inc / 2` (width in 4 ns units, half a clock per unit), computed by a sequential
multiplication whenever the width or the frequency changes and saturated at 100 %. A 17-bit
duty value would be far too coarse at low frequencies.

### Modulation (CH1)

The modulation signal is the CH2 DAC value, mapped to a signed value `2 · CH2 − 16383`
(centre 8191.5, exactly the centre of the symmetric waveform tables – a centre of 8192 would
cause a small FM carrier offset). With Ext.(VCO-IN) it is `(reg 0x2D − 0x800) · 8`.

| Mode | Implementation |
|---|---|
| FM | `inc_eff = inc + inc2 · m / 16384` (inc2 = deviation); two partial products that fit 18×18 multipliers |
| PM | phase offset `pm_dev · m`, 2^17 = 360° |
| FSK | increment switches to the hop frequency while keyed |
| PSK | phase offset 180° while keyed |
| AM | `out = c · (1 + d·m) / (1 + d)`; 1/(1 + d) computed sequentially per depth change |
| ASK | output at mid scale while not keyed |
| BURST | see below |

Keying source (FSK/ASK/PSK) and burst trigger come from reg 0x19: CH2 upper half, Counter
input, MANU key (reg 0x18, pressed = keyed) or Trig IN. The output pipeline has a fixed
latency, with or without modulation, so CH1 and CH2 stay aligned.

### Burst

* Idle: the accumulator holds 2^48 − 1 (end of a period); the output shows the value at the
  start phase (e.g. 0 V for a sine at 0°, low for a square).
* A rising edge of the source starts the burst; the first overflow begins period 1, the
  (N+1)th overflow ends it. Overflow counting is delayed by one clock for timing (valid up
  to 62.5 MHz, where overflows are at least two clocks apart).
* The end decision only drives one flip-flop; the one sample of period N+1 that the
  accumulator still produces is replaced by the idle value at the output.
* Count 0 = no output (firmware 1.8.0 writes 0 when MANU is selected); `count ≥ N` ends the
  burst, so a count reduced during a burst also stops it. Triggers during a burst are
  ignored.

### TTL / Sync outputs

Square/trapezoid/CMOS/pulse: high while the phase is below the threshold (follows the duty
cycle or pulse width); other waveforms: high for phase < 180° (rising edge at the upward
zero crossing of a sine). The signal is delayed so that its edges line up with the DAC
output (table 9, trapezoid 11, square 12 clocks). Port B/D are the inverted signals and are
forced low when the channel is off (mode 7).

### Uplink

* Master (reg 0x05 bits 6:5 = 00): Sync OUT carries the CH1 phase reference **without** the
  output delay, which compensates part of the slave's input latency.
* Slave (11): every rising edge at Sync IN (3-stage synchroniser) loads both channels with
  their start phase. Because each unit has its own TCXO, the slave re-synchronises every
  period; the remaining offset of a few tens of ns can be corrected with the slave's phase
  setting.
* Off (10): Sync OUT = Port A, Sync IN ignored.

## Frequency calibration

The firmware writes `25 · X` in µHz to 0x22:0x23 (X = reference, default 10 MHz). The DDS of
this design runs at 12.5 · X, so the frequency constant is `K = round(200000 · 2^64 / R)`.
After every write to 0x22/0x23 a sequential restoring division (82 steps plus rounding)
computes K; R outside about 9.81–10.2 MHz (or 0) selects the default `0x3_6F9B_FB3B`. The
counter gate times (0x24–0x27) are derived from X by the firmware, so generator and counter
are always consistent.

## Frequency counter (`freq_counter`)

* Event counter clocked directly by the selected input (global clock net, up to about
  125 MHz), Gray-coded into the system domain.
* Gate time: accumulator +2 per system clock against 5 × gate value (the firmware gives the
  gate in 50 MHz ticks), so the gate is exact for any X.
* COUNT mode: zero point on start, count while bit 1 is set.
* Pulse widths: high time then low time of one period at 125 MHz, reported doubled (4 ns
  units); results frozen until the next restart.
* "Stuck" detection: no edge for about 2 s → status bit for permanently high / low.

## MCP4822 driver (`mcp_drv`)

Writes the two outputs alternately, one 16-bit word about every 100 µs (SCK 5 MHz). Offset
with gain 2×, amplitude with gain 1×; CH2 has the outputs swapped (`SWAP = 1`). /LDAC is tied
low.

## Known limitations

* **Flash writes are not implemented yet** (planned, see below). Storing arbitrary waveforms
  from the PC software in the generator's flash does not work; waveforms already stored in
  the flash are used.
* Frequencies above about 62.5 MHz are not possible (half the sample rate); the firmware
  limits the 60 MHz model to 60 MHz.
* The TTL and Sync outputs have the jitter of the 125 MHz clock (±4 ns); only the analog
  square wave is edge-interpolated.
* The authentication handshake is ignored (no effect with the stock firmware).
* Sweep with the VCO-IN source was not tested.

## Future extension: flash writes

The PC software uploads arbitrary waveforms to the STM32, which stores them in the SPI flash
through the FPGA. This design currently ignores these writes, so an upload neither stores
nor damages anything. The register sequence below was derived from the firmware (1.4.2,
identical in 1.8.0); its effect on the flash was confirmed with the stock bitstream (see
[firmware-notes.md](firmware-notes.md#custom-waveform-upload)), the SPI traffic itself has not
been captured with the sniffer yet:

| Reg | Function (firmware view) |
|---|---|
| 0x17 | flash address (24 bit) |
| 0x11 | pulse 1 → 0: erase the 4 KB sector at 0x17 |
| 0x14 | data byte to program – **plain**, the FPGA has to bit-permute it into the flash format |
| 0x13 | pulse 1 → 0: program the byte from 0x14 at the current address; the address increments automatically |
| 0x16 | 1 → 0: begin a write sequence, 0: finish / flush |
| 0x15 | busy (polled with "read again" after every step) |

A waveform slot is 16 KB: the firmware erases four sectors and then writes the 16384 bytes of
plain sample data (8192 × 14 bit, little endian) exactly as received from the PC. The stock
FPGA stores every byte in the scrambled flash format – the inverse of the permutation it
applies when it reads (see [registers.md](registers.md#waveform-transfer-and-flash-access)):
data bit v0 goes to flash bit f5, v1 → f3, v2 → f6, v3 → f1, v4 → f0, v5 → f7, v6 → f2,
v7 → f4.

Implementation notes:

* W25Q16 commands: write enable `0x06`, sector erase `0x20` (4 KB, up to ~400 ms), page
  program `0x02` (up to 256 bytes within one page), read status `0x05` (bit 0 = busy). The
  simplest approach programs one byte per page-program command; buffering a page in block
  RAM is faster.
* Keep register 0x15 busy until the flash reports ready, so the firmware's polling paces the
  transfer.
* **Protect the whole bitstream area:** refuse erase and program commands below 0x05A000. A
  stray write there leaves the FPGA unconfigurable until the flash is reprogrammed with the
  USB-Blaster or an SPI programmer. The stock bitstream protects only the start of this area
  (up to a limit between 0x008000 and 0x058000) – an upload to 1.8.0 slot 47 killed it on the
  test unit.
* **Refuse, do not redirect.** The stock bitstream replaces a protected address by 0x1B0000;
  because that also happens to the sector erases, it damages custom slot 5. A refused
  command must not touch the flash at all.
* **Refuse addresses at or above the flash size** (2 MB on the W25Q16) instead of passing them
  to the flash, where they wrap around. Firmware 1.8.0 places the custom waveform slots at
  0x1A0000–0x29FFFF (a layout for a 4 MB flash); on the W25Q16 slots 25–64 wrap around into the
  bitstream area and the built-in waveforms of 1.4.2 – the cause of the reported flash
  corruption with the stock bitstream
  (see [firmware-notes.md](firmware-notes.md#custom-waveform-upload)). Read the flash size from
  the JEDEC ID (command `0x9F`: `EF 40 15` = W25Q16, 2 MB; `EF 40 16` = W25Q32, 4 MB) instead
  of building one bitstream per flash size, and allow no writes at all for an unknown ID.
* Still report busy and ready as usual for a refused command, so that the upload ends
  normally instead of hanging the firmware.
* Capture an upload from the PC software with the [sniffer](sniffer.md) (mode `a`) first and
  compare it with the table above.
